CLP plugin

How the CLP plugin analyzes logs

The plugin adds log analysis to an AI coding agent such as Claude Code or Codex. It has two parts. The first is a set of written instructions, called a skill, that the agent reads when someone asks it about logs. They tell it which steps to run, what to ask the person, and when to hand a piece of work to a second agent working alongside it, called a subagent. The second is a command, the program clp, that does the actual work: it compresses the logs, loads their structure and shapes, gathers the evidence, and computes the facts that back every figure in the report. The agent runs clp the way a person would in a terminal.

The diagram reads from top to bottom, following the data and the decisions. The steps in the center are shared. Between them the run splits into two routes, and each row pairs the step that does the same job on both. The rows are the jobs, not the skill's five numbered phases.

Claude Code is the one lightly pre-trained application today: its areas, and the queries built around its repetitive shapes, ship with the plugin, so a session skips the classification step. That is a starting point, not a limit: semantic search and any other query still run on the session's archive directly, which is how the agent goes deeper on what the user picks. Any other application is trained on the spot: its shapes are classified on its first run and cached, so later runs on that machine reuse them. Training here means sorting shapes into topics and writing queries for them; no model is trained. To pre-train another application, the plugin needs two things: the fields that identify its logs, so clp recognizes them (Codex and vLLM are already recognized this way), and the application's topics and queries, shipped with the plugin. Then every machine skips classification for it, starting with the first run.
